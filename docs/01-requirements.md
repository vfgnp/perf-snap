# PerfSnap 要件定義書（v1.1）

- 作成日：2026-11-23
- 状態：**確定**（§9 の未決事項を決定済み。Q5 のみ利用先での確認待ち）
- 名称「PerfSnap」は仮称

---

## 1. 背景と目的

### 1.1 背景
- 業務で使っている Windows 11 PC で、**定期的に操作が重くなる**事象が起きている。
  - キー入力の反映が遅れる（体感で約 2 秒の間が空く）
  - 画面の更新が遅れる
- 原因として、ウイルス対策・EDR などのセキュリティ製品の動作が疑われている。
- 現在はパフォーマンスモニターで調査しているが、次の問題がある。
  - 事象は**不定期で数秒しか続かない**ため、気付いてから手作業で記録を始めても間に合わない
  - 記録の開始に、管理者の PowerShell を開いてコマンドを打つ必要があり手間がかかる

### 1.2 目的
事象が起きたその場で、**ワンクリック（またはホットキー）で調査用データを保存できる**常駐ツールを作る。
ツール自体が調査対象の負荷にならないよう、**普段はほぼ CPU を使わない**ことを最優先する。

### 1.3 ねらい（成功の基準）
| # | 基準 |
|---|---|
| G1 | 事象に気付いてから **3 操作以内・5 秒以内**に保存を始められる |
| G2 | 気付く**前**の数十秒間のデータも残せる（後追いでは原因を逃すため） |
| G3 | 常駐中、ツールの CPU 使用率が平均 **0.1% 未満** |
| G4 | 保存したデータを、既存の分析ツール（パフォーマンスモニター、Windows Performance Analyzer）でそのまま開ける |

## 2. 対象範囲

### 2.1 対象とするもの
- データの**取得・保存**と、その操作の簡略化
- Windows 標準の記録機能を使う
  - **パフォーマンスカウンター**（`logman.exe`、パフォーマンスモニターと同じ仕組み）
  - **ETW トレース**（`wpr.exe` = Windows Performance Recorder、Windows 11 に標準搭載）

### 2.2 対象としないもの
- 取得したデータの**分析・診断**（WPA やパフォーマンスモニターで人が行う）
- 原因の自動特定、セキュリティ製品の設定変更
- 複数 PC からのデータ収集、サーバーへの送信
- Windows 11 以外の OS

## 4. 機能要件

優先度：**必須**＝初版に入れる、**推奨**＝できれば初版、**任意**＝将来

### 4.1 常駐・操作

| ID | 機能 | 優先度 | 内容 |
|---|---|---|---|
| F-01 | タスクトレイ常駐 | 必須 | 起動するとタスクトレイにアイコンを表示する。ウィンドウは常時は出さない |
| F-02 | 状態の表示 | 必須 | アイコンの見た目で「待機中／記録中／保存中」が分かる |
| F-03 | 右クリックメニュー | 必須 | 記録の開始・停止、保存、プロファイル選択、出力フォルダを開く、終了 |
| F-04 | グローバルホットキー | 必須 | どのアプリを操作中でも、キー操作で「今すぐ保存」できる（例：Ctrl+Alt+Shift+P）。キーは設定で変更可 |
| F-05 | 通知 | 推奨 | 保存の開始・完了を Windows の通知で知らせる |
| F-06 | ログオン時の自動起動 | 推奨 | 管理者権限のまま、ログオン時に自動で常駐を始める（UAC の確認を毎回出さない方式） |

### 4.2 記録

| ID | 機能 | 優先度 | 内容 |
|---|---|---|---|
| F-10 | 直前データの保存（フライトレコーダー方式） | 必須 | メモリ上で常に直近の一定時間（例：60 秒）を記録し続け、操作した瞬間に**それまでの分**をファイルに保存する。事象に気付いた時点ではもう遅い、という問題への対策 |
| F-11 | 時間指定の記録 | 必須 | 「今から N 秒間記録する」を実行できる |
| F-12 | 継続的なカウンター記録 | 必須 | 軽いカウンター（CPU、ディスク、メモリ、DPC/割り込み、プロセス別 CPU など）を低い頻度で長時間記録し、事象がいつ起きたかを後から追えるようにする |
| F-13 | プロファイル | 必須 | 「何を・どの細かさで記録するか」の組み合わせを名前付きで保存し、メニューから選んで実行できる（§4.3） |
| F-14 | メモの記録 | 推奨 | 保存時に「何が起きたか」の一言メモを添えられる。メモと時刻は保存データと同じフォルダに残す |
| F-15 | 遅延の自動検知 | 必須 | ツール自身のタイマーが予定より大きく遅れたら（例：1.5 秒以上）、操作が止まったとみなして自動で保存する。追加の負荷がほぼない方法で行う |

### 4.3 初期プロファイル（案）

| プロファイル | 記録方式 | 主な内容 | 想定する使い方 |
|---|---|---|---|
| 軽量監視 | カウンター（logman） | CPU・ディスク・メモリ・DPC/割り込み・プロセス別 CPU/IO、15 秒間隔 | 常時オンで、いつ起きたかを残す |
| 入力遅延の調査 | ETW（wpr） | CPU 使用状況、ディスク I/O、ファイル I/O、ミニフィルター（セキュリティ製品が使う仕組み）、DPC/割り込み | 事象が起きたらホットキーで保存 |
| 詳細 | ETW（wpr） | 上記＋待機状態の分析など | 担当者が意図して短時間だけ使う |

> セキュリティ製品は、ファイルのアクセスを横取りして検査する「ミニフィルタードライバー」の仕組みで動くことが多い。このため、ファイル I/O とミニフィルターの記録を初期プロファイルに含める。

### 4.4 保存データの管理

| ID | 機能 | 優先度 | 内容 |
|---|---|---|---|
| F-20 | 出力フォルダ | 必須 | 保存先を設定できる。1 回の保存ごとに「日時」のサブフォルダを作る |
| F-21 | 容量の上限 | 必須 | 出力フォルダの合計が上限（例：10 GB）を超えたら、古いものから自動で削除する。空き容量が少ないときは保存しない |
| F-22 | ファイル形式 | 必須 | カウンターは `.blg`（パフォーマンスモニターで開ける）、トレースは `.etl`（WPA で開ける） |
| F-23 | 調査情報の添付 | 推奨 | 保存時に PC 名、OS ビルド、CPU・メモリ、実行中のプロセス一覧などをテキストで一緒に残す |

### 4.5 設定・ログ

| ID | 機能 | 優先度 | 内容 |
|---|---|---|---|
| F-30 | 設定ファイル | 必須 | 設定は JSON ファイルで持つ。画面からも変更できる |
| F-31 | ツール自身のログ | 必須 | 操作・エラーをログファイルに残す（サイズ上限つき） |
| F-32 | 後片付け | 必須 | ツールの終了時・異常終了後の次回起動時に、ツールが始めた記録を確実に止める（記録が残り続けて負荷になるのを防ぐ） |

## 5. 非機能要件

| 分類 | ID | 要件 |
|---|---|---|
| 性能（最重要） | N-01 | 待機中のツールの CPU 使用率：平均 0.1% 未満 |
| | N-02 | 待機中のメモリ使用量：50 MB 以下 |
| | N-03 | 記録中の追加負荷：軽量監視で CPU 1% 未満。ETW プロファイルの負荷は実測して文書に残す |
| | N-04 | ホットキーを押してから保存開始まで：1 秒以内 |
| 信頼性 | N-10 | ツールが落ちても、記録が残り続けない（F-32） |
| | N-11 | ディスクを使い切らない（F-21） |
| 安全性 | N-20 | 外部との通信をしない |
| | N-21 | ツールが削除するのは、自分の出力フォルダ内で自分が作ったデータだけ |
| | N-22 | 保存データには PC 内のファイル名やプロセス名が含まれる。この扱いを README に明記する |
| 導入 | N-30 | インストール不要で、exe を置けば動く |
| | N-31 | アンインストールは「自動起動の解除＋フォルダ削除」で完了する |
| 保守 | N-40 | ソースコードとドキュメントを GitHub で管理する |

## 6. 制約・前提

1. **管理者権限**が必要。対象の PC で管理者権限を使えることを前提とする。
2. 使うのは Windows 標準の `logman.exe` と `wpr.exe` のみ（両方ともこの PC に存在を確認済み）。追加のドライバーは入れない。
3. **導入先のセキュリティ製品や Windows のアプリ制御が、署名のない exe を実行禁止にする可能性がある。** 導入先の管理者（IT 部門など）への確認が必要になる場合がある。
4. PC への持ち込み・実行について、導入先のルールに従う。
5. 分析には Windows Performance Analyzer（WPA）が別途必要（Microsoft Store から無料で入手可）。

## 7. リスク

| リスク | 影響 | 対策案 |
|---|---|---|
| セキュリティ製品がツールを止める・隔離する | ツールが動かない | IT 部門に事前確認。必要ならコード署名や除外登録を相談 |
| ETW の常時記録（F-10）が負荷になる | 調査対象を悪化させる | 負荷を実測し、軽い内容に絞ったプロファイルを用意。常時オンにするかは利用者が選ぶ |
| 他のツールが同時に ETW を使っている | 記録を開始できない | エラーを分かりやすく通知し、ログに残す |
| 保存データに PC 内の情報（ファイル名・プロセス名など）が含まれる | 情報漏えい | 社外へ送らない運用を README に明記。GitHub にはデータを上げない |

## 9. 決定事項

| # | 項目 | 決定 | 理由 |
|---|---|---|---|
| Q1 | 開発言語 | **C#（.NET 10 LTS / WinForms）** | トレイ常駐やホットキーを素直に作れて、1 つの exe にできる。PowerShell の exe 化はセキュリティ製品に誤判定されやすいため不採用。ドラフトでは .NET 8 としていたが、.NET 8 のサポートは 2026-11-10 に終了したため、後継の LTS である .NET 10（2028-11 までサポート）に変更 |
| Q2 | exe の形式 | **.NET 込みの単体 exe** | 対象の PC に追加のソフトを入れずに動く |
| Q3 | GitHub リポジトリの公開範囲 | **公開**（v1.1 で変更） | 当初は非公開としていたが、公開に変更した。特定の組織の事情はドキュメントに書かない |
| Q4 | 遅延の自動検知（F-15） | **初版に入れる**（優先度を「必須」に変更） | 手動では間に合わない事象を拾える。負荷もほぼない |
| Q5 | 業務用 PC での実行許可 | **確認待ち** | 開発と並行して、利用者が導入先の管理者に確認する |
| Q6 | 開発用のソフトの導入（開発 PC） | **.NET 10 SDK（10.0.404）を導入済み** | — |
